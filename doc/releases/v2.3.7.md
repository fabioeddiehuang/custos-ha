## 一、版本定位

让「配置待生效」徽标**自动消失**：改配置 / 重装后，若节点确实已落实变更，徽标无需人工点「已执行」即自动清除；
只有真正未落实的才保留，根治「点一下就消失、其实没生效」的假象，以及反复 regen 反复点的死循环。

## 二、新增功能

- `deploy_actions` 每个动作新增 `verify` 字段，声明「如何证明已生效」：
  - `db_uptime`：节点 DB `Uptime` < 待生效时长（常用于 my.cnf 静态参数 / 重建容器类）；
  - `proc:<svc>`：节点 agent `/stats` 的 `agent_started_at` / `keepalived_started_at` 晚于 `pending_since`（重启服务类）；
  - `db_alive`：节点库可连通（首次部署类，装完 60s 内自动消除）；
  - `manual`：exec / 首次部署等仍人工确认。
- `node_gen.verify_node_pending` 只读核验并自动移除已落实的动作（取证条件 `db_uptime` / `proc:*` / `db_alive`）；
- `monitor` 每 60s 跑 `verify_pending_all`；`/api/nodes/{ip}/pending` 读取前先核验；`nodes.html` 每 30s 轮询隐徽标；
- `nodes.pending_actions` / `pending_since` 落库（新增字段，启动自动迁移）。

## 三、兼容与升级

- 旧 JSON 无 `verify` → 按 `manual` 保留（兼容存量，不会出现徽标凭空消失或凭空挂死）。
- 生效需：**重建管理器** + **regen 节点** + `docker compose restart custos-node-agent` 三步。
- ⚠ 存量已「挂死」的「首次部署」条目，代码不会自动迁移已有 JSON；需把它对应的 `verify` 改为 `db_alive` 才会自动消除（重装一次节点即可）。

## 四、验收

- [ ] 改 my.cnf 静态参数 → regen → 节点重建容器 → 约 60s 内徽标自动消失；
- [ ] 改 keepalived 配置 → regen → 重启 keepalived → 徽标自动消失；
- [ ] 未落实的变更徽标持续保留，并能在「待生效操作」中看到原因。
