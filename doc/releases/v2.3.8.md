## 一、版本定位

修掉「更新配置后反复点修复却没效果」这一类体验硬伤：徽标不能点一下就消失、凭证不能被越修越空、
半同步不能假装修好、手动修复不能连点刷屏、只读账号操作失败要有明确提示。

## 二、修复（Fixed）

### 1. 待生效徽标真实性（ack 核验门禁）
- **根因**：`ack_node_pending` 原本只有一句 `UPDATE nodes SET pending_actions=''`，不连节点、不核验、不区分条目，
  点一下徽标就消失。UI 把「我知道了」呈现成「已完成」，运维以为生效，实际节点配置没变 → 问题复现 → 再 regen 再点。
- **修复**：`ack_node_pending(ip, force=False)`：
  - `manual` 类允许清除；
  - `db_uptime` / `proc:*` 类**只有自动核验确认落实才清除**，未落实的一律保留并回传 `reason`（为什么没生效）；
  - `force=True` 人工兜底（DB 在 regen 前就重启过 / 节点无 agent 等核验永不满足场景）。
- `api.py::nodes_ack_deploy` 同步支持 `?force=1` 并回传 `kept`；`nodes.html::ackDeploy` 展示原因 + 「仍然清除」按钮。

### 2. 凭证解密致命 bug
- **根因**：`decrypt()` 失败原返回空串 → 上层 `encrypt("")` 原样落库 → **真实凭证被永久覆盖为空口令**，
  且空口令会渲染进 `fix-node-creds.sql` / `ha_check.conf` 下发到节点，表现为「越修越坏」。
- **修复**：`decrypt()` 失败**原样返回密文**（与模块文档一致），凭证不丢，故障表现为「密码不对」+ 日志可定位。

### 3. 待生效列表缺列
- `list_nodes(cluster_id)` 漏选 `pending_actions` / `pending_since` → 按集群筛选后「待生效」徽标与按钮全消失。已补列。

### 4. 核验可观测
- `verify_node_pending` 未落实时写 `reason`（连不上 DB / Uptime 未归零 / agent 不可达 / 时钟漂移可能误判），不再只留一个哑徽标。

### 5. 半同步假成功
- **根因**：`ensure_semisync_runtime` 只 `SET source/replica` 且 `except: pass`，然后**无条件 return True** →
  monitor 每 60s 记一次「自愈成功」但半同步从未开。
- **修复**：两套命名都 `SET`（MySQL8 `source/replica`；MariaDB ≤11.4 只有 `master/slave`），并 **`SHOW VARIABLES` 复核真的 ON 才算成功**。
  注意：该函数开头 `flavour != F_MYSQL8 → return False 跳过`，**MariaDB 半同步由 my.cnf 注入、不走运行期 SET GLOBAL**。

### 6. /api/heal 防刷
- 加了 **15s 点击冷却**（此前手动点击无限频，连点会反复 `STOP/START SLAVE`）；
- 失败告警按 **(集群, 主机, 端口)** **去重**（此前每次失败无脑 INSERT 一条 unresolved，点 10 次多 10 条 → 「报错不断」的观感来源）。

### 7. 只读账号 403 无提示
- **根因**：`auth_required` 对非 GET 且 `role=viewer` 抛 403，前端只读 `d.msg`，而 403 返回的是 `detail` → 用户只看到「生成失败」以为是故障。
- **修复**：detail 写明「当前为只读账号…请改用管理员登录」；前端改为 `d.msg || d.detail || …`。
  **排查「操作失败」先看日志是不是 403**：viewer 账号所有写操作都被拦（账号：`admin`=管理员 / `test`=只读）。

### 8. 待生效徽标挂死
- **根因**：①「首次部署」动作 verify 默认为 `manual`，永不自动消除；②`fresh=not _old_snap` 只看生成目录是否为空，
  目录若被清空/迁移后重新生成，**已上线节点会被误报「首次部署」**。
- **修复**：首次部署动作改 `verify="db_alive"`（节点数据库能连通即视为已部署，装完 60s 内自动消除）；
  `fresh` 判定改为 `not _old_snap and not _prev_fp`（历史指纹非空 ⇒ 生成过 ⇒ 不算首次）。
