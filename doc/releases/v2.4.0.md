## 一、版本定位

**让 MariaDB 集群"自己跑"**：备份可信且可观测、一致性自动巡检、耗时操作可追踪、能出可交付的报告。
v2.3 解决"对不对"，v2.4 解决"稳不稳、看不看得见"。

## 二、功能规划

### F1. 备份调度增强 `P1`

- **功能目的（Why）**
  - 现状：调度**已实现**（`monitor.py` + settings：`BACKUP_SCHEDULE_ENABLED` / `BACKUP_INTERVAL_HOURS` / `BACKUP_RETENTION_DAYS` / `BACKUP_TARGET=slave` / `BACKUP_WITH_DATA`）。
  - 但缺：保留**份数**、失败**重试**、成功率与耗时**可观测**。备份失败只能翻日志，容易长期无人发现（"以为一直在备份"）。
- **功能目标（验收标准）**
  1. 保留策略支持"按天数 + 按份数"两种，可同时生效
  2. 备份失败自动重试（可配次数与间隔），仍失败则**触发告警**
  3. 新增备份可观测面板：成功率、耗时趋势、**RPO（距上次成功备份时长）**
  4. 备份目标 `BACKUP_TARGET=slave` 在无可用从库时回退主库，并在结果中标记实际来源
- **涉及模块**：`app/monitor.py`（调度）、`app/backup.py`、`app/api.py`、仪表盘 / 备份页
- **依赖**：v2.3-F2（位点记录，用于计算 RPO 与可恢复性）

### F2. 备份自动校验 `P1`

- **功能目的（Why）**
  - "备份成功"不等于"可以恢复"。目前备份产出后无任何校验，损坏 / 半截文件可能长期不被发现。
- **功能目标（验收标准）**
  1. 备份完成后自动抽检：关键表行数、`CHECKSUM TABLE` 抽样比对源库
  2. 备份集标记「可信 / 存疑」，存疑项在备份历史中**显著提示**并告警
  3. 校验失败不影响备份文件保留，仅标记与告警（绝不静默删除）
- **涉及模块**：`app/backup.py`、`app/api.py`、`app/templates/backup.html`
- **依赖**：v2.3-F2

### F3. 一致性校验自动化 `P2`

- **功能目的（Why）**
  - 现状：`consistency`（表行数 / `CHECKSUM TABLE` 两档，纯只读）需**手动触发**，容易忘记，分歧往往等到复制报错才暴露。
- **功能目标（验收标准）**
  1. 支持按策略周期自动运行（开关 + 周期 + 时间窗，避开业务高峰）
  2. 结果落趋势：可查看历史分歧变化
  3. 发现分歧时告警（邮件 + 页面提示）
- **涉及模块**：`app/consistency.py`、`app/monitor.py`、`app/api.py`
- **依赖**：无

### F4. 巡检报告导出 `P2`

- **功能目的（Why）**
  - 交付 / 汇报 / 客户验收场景需要一份"这个集群现在健康吗"的书面报告，目前要人工从多个页面拼凑。
- **功能目标（验收标准）**
  1. 一键生成集群健康报告：拓扑与角色、复制状态与延迟、配置漂移、备份概况、慢查询 TopN、近期告警与切换
  2. 支持导出（HTML / PDF），含生成时间与集群标识
  3. 报告只读，不触发任何变更操作
- **涉及模块**：新增报告聚合接口、`app/api.py`、`app/templates/`（报告页）
- **依赖**：F1、F3（数据完整性）

### F5. 任务中心持久化 `P1`

- **功能目的（Why）**
  - 现状：只有 `rebuild` 有 `task_id`，且存在**内存字典 `_TASKS`**，管理器重启即丢失、页面刷新看不到历史。
  - 备份 / 恢复 / 一致性 / 切换等耗时操作目前是同步阻塞，前端只能"点了干等"。
- **功能目标（验收标准）**
  1. 统一任务模型：**持久化**（新表） + 进度百分比 + 日志 + 操作人 + 开始/结束时间
  2. 覆盖：rebuild / backup / restore / 一致性校验 / 切换
  3. 支持查询历史任务列表与详情，重启后不丢失
  4. 前端统一进度展示与失败原因查看
- **涉及模块**：`app/rebuild.py`（现有内存实现改造）、新增任务表（`app/db.py`）、`app/api.py`、前端
- **依赖**：无
