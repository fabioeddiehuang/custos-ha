# v2.3.10 凭证加密默认关闭 + 复制自愈保底

> 发布日期：2026-09-14 ｜ 类型：修复 / 稳定性（向后兼容：管理库表结构不变）

## 目的
修复「节点安装后复制中断、节点不自动加入集群」这一重大故障，并从设计上消除
「重装应用 / SECRET_KEY 变动 → 存量凭证集体失效」的高危失效模式。

## 关键变更

### 1. 凭证静态加密改为**默认关闭**（可按需开启）
- 新增 `CRED_ENCRYPTION`（env / config，默认 `off`）。关闭时凭证明文落库，
  **完全不依赖任何密钥**，SECRET_KEY 变动 / 重装 / 重建镜像都不会再导致存量凭证失效。
- 有合规或高安全需求时置 `CRED_ENCRYPTION=on` 启用（compose 已显式透传该变量）。
- `decrypt()` 无论开关如何都照常解 `ENC1:`，保证关闭后历史密文仍可读。
- **为什么默认关闭**：凭证密钥（`data/cred.key`）与密文（管理库）在同一台机器、
  同一份备份里，加密实际只防「仅泄露管理库 dump」一种场景；代价却是「密钥一变
  全集群复制瘫痪且静默失败」。可用性风险 >> 实际安全收益。

### 2. 凭证密钥三层保底（启用加密时）
- **持久化**：主密钥首次启动自动落 `data/cred.key`（权限 0600），**不再随 SECRET_KEY
  变化** → 重装 / 重建镜像不影响存量凭证。存量部署升级时以「当前派生密钥」为种子写入，
  主密钥不变，升级零影响。
- **钥匙串回退**：`decrypt()` 依次尝试 `CRED_KEY` → `data/cred.key` → `SECRET_KEY` 派生，
  任一命中即成功；单一来源失效不再导致集体解不开。
- **无密钥兜底**：连 SECRET_KEY 都不可用时退化为随机密钥（原实现在此直接 `raise`，
  会让整个应用起不来）。
- **反向迁移**：`db.migrate_decrypt_credentials()` —— 加密关闭时启动自动把仍可解开的
  `ENC1:` 还原为明文，彻底解除密钥依赖；解不开的一律跳过、**绝不改写**。

### 3. 修复（重大）：复制口令为 ENC1 密文导致复制集体瘫痪
- **现象**：`CHANGE REPLICATION SOURCE` 报
  `1470 - String 'ENC1:...' is too long for MASTER_PASSWORD (should be no longer than 96)`，
  随后监控判定「源库不可达」并跳过自愈，复制永久卡死。
- **根因**：`crypto.decrypt()` 解密失败时按设计【原样返回密文】（绝不返回空串，
  以免空口令永久覆盖真实凭证），密文随即被当成明文口令拼进 SQL。
- **修复**：`make_slave_of` 入口拦截仍未解密的 `ENC1:` 口令，直接返回失败并给出
  可操作结论，**绝不把密文写进复制配置**；`ha_monitor` 口令同类情况只告警不阻断
  （保住 `connect_robust` 的 root 回退，避免扩大故障面）。

### 4. 修复：`_repoint_slave` 返回值契约与假成功
- 返回值统一为 `(ok, msg)` 元组。原返回裸 bool，而 `monitor.py` 两处按
  `ok_r, msg_r = _repoint_slave(...)` 解包 → 抛 `TypeError`；且该调用无 try 保护，
  会中断整个节点循环，使其后的 `ensure_topology` **永不执行**（节点不自动加入、
  复制断了也无人自愈）。现两处调用均就地兜异常。
- 重试 8 次仍未达双 Yes 时返回**真实失败**（原无条件 `return True` 属假成功，
  会让 `ensure_topology` 打印「已重指向新主」且完全不告警）。

### 5. 修复：`custosctl node install` 不支持容器版 MySQL / MariaDB
- 根因：节点包 compose 文件名为 `docker-compose.yaml`，而 `custosctl` 的 `is_docker`
  检测读的是 `docker-compose.yml` → 容器节点被误判为裸机 → 找不到 Install 脚本而失败
  （表现：只有裸机 MariaDB 装得上）。
- 修复：新增 `_cf()` 统一解析当前目录 compose 文件名（`.yaml` 优先、回退 `.yml`）。
- 三种形态现已齐备：容器 MySQL、容器 MariaDB（`docker compose up -d`）、
  裸机 MariaDB（`bash Install 脚本`）。

### 6. 卸载保底：密钥保险库（`/var/lib/custos`）

- **问题**：密钥原先只存在于项目目录内的 `data/cred.key`。`-f` 卸载会删 `data/`，
  用户直接删掉整个项目目录更会让密钥消失 —— 管理库里所有 `ENC1` 凭证随之永久解不开。
- **方案**：在**项目目录之外**建立保险库 `/var/lib/custos/`：
  - `scripts/uninstall.sh`：卸载前（无论是否 `-f`）先把 `data/cred.key`、`data/secret_key`
    镜像过去（权限 600），并在输出中明示保留位置；该目录**不会被卸载删除**。
  - `install.sh`：重装时若 `data/` 下缺失则自动从保险库取回；反之若项目内已有密钥，
    也顺手同步一份到保险库，保证保险库始终最新。
  - `crypto.py`：保险库路径纳入解密钥匙串；启动时 `bootstrap()` 若发现 `data/cred.key`
    缺失而保险库存在，会自动回补并写回 `data/`。
- **效果**：满足「除非手动删除保险库，否则卸载 / 删除项目目录都不会让凭证失效」。
  需连同凭证一起彻底作废时，手动删除 `/var/lib/custos` 即可。

### 7. 启动自检：解不开的凭证主动告警

- **为什么必须做**：凭证解密失败是**完全静默**的 —— 管理库读出密文，上层当口令直接用，
  只有等到复制建立时把密文拼进 `CHANGE MASTER` 报 `1470` 才暴露；届时现象是
  「复制起不来 / 源库不可达」，与「密钥不匹配」毫无字面关联，排查成本极高。
- **实现**：`init_db` 启动时调用 `db.startup_credential_check()`：
  - 有解不开的凭证 → 启动日志 `docker logs` 打印红色分块明细（集群/节点 · 名称 · 字段）；
  - 同时按集群聚合写入 `alerts` 表（`alert_type='cred_key'`、状态 `open`），Web 告警中心可见；
  - 24 小时内同内容不重复写，避免每次重启刷屏。
  - 直接写 `alerts` 表而**不用** `alerts.send_alert`（后者是邮件通道，未配 SMTP 时只 print，
    无法保证界面可见）。
- 体检结果新增 `cluster_id` 字段，便于按集群聚合与定位。

### 7. 一键「批量重置复制口令」

- 设置 → 凭证加密 → 新增按钮「批量重置复制口令」。适用场景：复制口令漂移/需定期轮换。
  生成新的 repl_pass 落库，在每个节点上重置 ``replication`` 账号密码（任意节点成为主库时口令一致），
  对从库以新口令重新挂载复制（``make_slave_of``，GTID 自动定位、不丢数据）。
- 实现：`db.reset_repl_password(cluster_id)` 复用 ``ha_client.reset_replication_creds_on_master``
  （主库重置复制账号，强制 mysql_native_password + 按从库 IP 建同名同密账号）与 ``make_slave_of``
  （从库以新口令重挂，VIP/GTID 分叉守卫齐备）；当前主库取自 ``state.get_current_master``，缺失时按
  ``read_only`` 探测可写节点兜底。
- ⚠ 依赖 manager 能用 ha/root 连上节点（口令须可用）；若 root 也解不开，请改用「从节点包回填明文」或手动重置。


- 设置 → 凭证加密 → 新增按钮「从节点包回填明文」。适用场景：**重装 / 重建管理器**导致
  管理库密文解不开、复制中断。节点生成包（``generated_nodes/<ip>/``）里含节点 MySQL
  **当前实际使用**的明文口令（init SQL / fix-node-creds.sql 的 ``... BY '<明文>'``、
  compose 的 ``MARIADB_ROOT_PASSWORD``），直接回填即可让复制恢复，**无需旧密钥、无需重设节点**。
- 实现：`db.recover_creds_from_node_packages()` 扫描全部节点包，解析 ``账号→口令``（覆盖
  MySQL ``IDENTIFIED WITH ... BY``、``SET PASSWORD ... = PASSWORD('')``、MariaDB
  ``USING PASSWORD('')``），回填集群级 ha/repl/app 口令与逐节点 root 口令；按 IP 匹配部署单元目录名。
- 依赖文件、不连节点 DB；节点包缺失时返回明确提示并引导手动重录。

## 升级 / 迁移注意（重要）
- 若此前凭证已处于「解不开」状态，反向迁移会跳过该值，升级后需在「集群设置 / 节点」
  **重新录入一次口令**，此后按新策略存储，永久免疫。
- 升级管理器镜像：确认 `.env` 的 `VERSION=v2.3.10`（单一来源）后执行
  `./scripts/deploy.sh up -d --build`。
- 如需启用凭证加密：把 compose 的 `CRED_ENCRYPTION` 改为 `"on"` 并重建；此后密钥
  持久化在 `data/cred.key`，重装不再失效。
