# v2.3.9 节点部署目录结构归整

> 发布日期：2026-09-13 ｜ 类型：结构优化（向后兼容：管理器协议与 DB 表结构不变）

## 目的
把 `generated_nodes/<ip>/` 节点包的符号文件（配置 / SQL / 安装脚本 / 节点 agent）从「全部平铺在根目录」归整为
按数据库风味 + 用途分目录，解决多风味节点混部、安装脚本 / 日志 / 配置互相踩、以及容器 MariaDB 与 docker compose
挂载路径错配的问题。

## 关键变更
- **配置 / SQL 子目录**：MySQL 节点 → `mysql8.0/conf/`（init.sql、ha-overrides.cnf）；MariaDB 节点 → `mariadb12.3.3/conf/`（my.cnf、docker-my.cnf、init_mariadb.sql、fix-node-creds.sql、custos-ha-logrotate.conf）。
- **安装脚本子目录**：`mysql8.0/scripts/`、`mariadb12.3.3/scripts/`（Install / Uninstall / prepare-logs / update-node）。
- **节点 agent 独立子目录**：`agent/`（`node_agent.py`、`node-agent.service`）。
- **keepalived 仍在节点包根**：`keepalived/keepalived.conf` + `chk_*.sh`（独立进程，路径不变）。
- **日志统一**：裸机 Mariadb 日志挂到 `/data/custos-ha/logs/mariadb`；`Install-ha-mariadb-Node.sh` 在包内建 `logs -> /data/custos-ha/logs/mariadb` 软链。
- **compose 挂载修正**：容器 MariaDB 的 `docker-my.cnf` / `init_mariadb.sql` 改挂 `mariadb12.3.3/conf/`（不再 `./` 平铺）；MySQL docker 节点挂 `mysql8.0/conf/`。
- **安装脚本 `$SCRIPT_DIR` 收敛**：`Install-ha-mariadb-Node.sh` 的 `$SCRIPT_DIR` 现在只用于定位节点包根（解析 `NODE_ROOT` / `CONF_DIR`），不再 `$SCRIPT_DIR/custosctl` 拷贝自身；custosctl 改由 `custosctl node prepare` 显式下发。
- **节点包自带 custosctl**：包内 `custosctl` 支持 `node prepare`（下发 agent 文件 + 软链 logs + 校验必备文件 + 清理孤立 `generated_nodes/<ip>` 单元）；`scripts/setup.sh` 改为 `sudo custosctl node prepare` 自检。
- **extra_files 路径同步**：`nodes.extra_files` 里所有 `init_sql` / `install_script` / `agent_file` 等下载地址改指 `conf/`·`scripts/`·`agent/` 子目录。
- **部署待生效动作修正**：`deploy_actions` 的执行命令改为归整后相对路径（Install 脚本、`fix-node-creds.sql`、`prepare-logs.sh`）；凭证同步 / 重生成函数把 init SQL 与 fix SQL 写到 `conf/` 子目录（与 `generate_node` 一致）。

## 升级 / 迁移注意（重要）
- **存量节点包目录已变**：所有存量节点须 `regen` 后重新 install 才能用上新布局（docker 节点：regen + `docker compose up -d`；裸机节点：regen + 重跑 `Install-ha-mariadb-Node.sh`）。仅 regen 不重装 → 节点仍读旧平铺路径 → 启动失败。
- 改 `node_agent.py` 仍须「重建管理器镜像 + regen 节点 + restart custos-node-agent」三步生效。
- 升级管理器镜像用 `.env` 的 `VERSION`（单一来源）：`./scripts/deploy.sh up -d --build`。

- 真实渲染 `render_mariadb_compose` / `render_baremetal_compose` 确认挂载路径正确；MySQL 内联 compose 经源码 grep 确认。
