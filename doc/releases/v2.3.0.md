## 一、版本定位

**不加新功能，只补地基**：解决「备份能不能信、凭证会不会泄、维护会不会被切换打断」三件事。
这一版是后续所有自动化（单元分发、升级编排、PITR）的前置，必须先做完。

## 二、功能规划

### F1. 管理库凭证加密存储 `P0`

- **功能目的（Why）**
  - 现状：`nodes.root_pass`、`clusters.ha_pass / repl_pass / app_pass` **明文入库**。
  - 风险：任何能读管理库的人（或拿到管理库备份、dump 文件）即可直接拿到生产库 root 口令。
  - 更关键：**v2.5 单元分发会把凭证写进节点部署文件**，明文凭证下发到目标机属于不可接受的风险敞口。
- **功能目标（验收标准）**
  1. 管理库中不出现明文口令（对称加密存储，密钥来自环境变量或密钥文件，不入版本库）
  2. 全读取路径无感知改造：`ha_client.node_root` / `node_gen` 渲染 / `backup._conn` / `failover`
  3. 既有集群**平滑迁移**：管理器启动时自动加密存量明文字段，无需人工干预
  4. 密钥缺失或错误时**明确报错**，绝不静默降级为明文或跳过
- **涉及模块**：`app/db.py`、`app/clusters.py`、`app/ha_client.py`、`app/node_gen.py`、`app/backup.py`、`app/failover.py`、`app/config.py`
- **依赖**：无；但 **v2.5-F1 单元分发依赖本项**
- **非目标**：本次不做密钥轮转（rotate）界面，留待后续

### F2. 备份一致性快照 + GTID / binlog 位点入 meta `P0`

- **功能目的（Why）**
  - 现状：`backup.py` 逐表 `SELECT` 导出，**没有开启一致性事务**。备份期间若有写入，恢复出来的数据**跨表不一致**（例如订单表与库存表对不上）。
  - 现状：meta 不记录 GTID / binlog 位点，因此**无法做时间点恢复（PITR）**。
- **功能目标（验收标准）**
  1. 备份开始时开启一致性快照事务（MariaDB 与 MySQL 各自实现，互不影响）
  2. meta 记录位点：MariaDB 记 `gtid_binlog_pos` / `gtid_slave_pos`；MySQL 记 `gtid_executed` + binlog 文件位点
  3. **验收用例**：备份期间持续写入，恢复后跨表关联数据一致（外键/业务校验通过）
  4. 老备份（无位点字段）仍可正常列出、预览、恢复，不报错
- **涉及模块**：`app/backup.py`（`run_backup`）
- **依赖**：无；**v3.0-F2（PITR）依赖本项**
- **非目标**：本版只做位点**记录**，不做基于位点的恢复（PITR 在 3.0）

### F3. 维护模式 begin / end `P0`

- **功能目的（Why）**
  - 现状：做维护、重建从库、升级时，`monitor` 仍可能触发**自动切换**，把正在操作的节点切走，造成业务中断与误判。
  - Orchestrator 等同类产品均提供 `begin/end-maintenance`；这也是后续「版本升级编排」的必要前置。
- **功能目标（验收标准）**
  1. 支持按**集群 / 节点**开启维护窗口（含原因、时长、操作人、开始时间）
  2. 窗口内**抑制自动切换与告警**，手动切换需二次确认
  3. 窗口到期自动结束；也支持手动提前结束
  4. 维护状态在仪表盘 / 集群页**显著可见**，避免"忘了关"
- **涉及模块**：新增维护状态存储（settings 或新表）、`app/failover.py`（`do_failover` 判断）、`app/monitor.py`（自动切换判断）、`app/api.py`、前端页面
- **依赖**：无；**v3.0-F3（版本升级编排）依赖本项**
- **非目标**：不做定期维护计划（如每周二凌晨自动维护），仅支持手动开关与到期自动结束

### F4. 备份按库分文件 + index.json `P1`

- **功能目的（Why）**
  - 现状：全库备份是**单个大 gzip**，恢复"指定库"需把整个文件读进内存按 `USE` 段过滤；大库场景内存压力大、速度慢。
- **功能目标（验收标准）**
  1. 全库备份产出：每库一个 `.sql.gz` + 一个 `index.json`（备份集 ID、库列表、位点、各库大小）
  2. 恢复指定库时**只读取对应库文件**，不再全量解析
  3. 兼容旧的单文件格式：仍能列出、预览、按库恢复
- **涉及模块**：`app/backup.py`、`app/templates/backup.html`
- **依赖**：F2（位点记录）

### F5. MariaDB 三形态日志采集确认 `P1`

- **功能目的（Why）**
  - MariaDB **无 `mysql.error_log` 表**（MySQL 8.0 才有），错误日志只能靠 `LOAD_FILE` + `secure_file_priv=''`。
  - 需逐一验证真的读得到；否则排障时"错误日志"面板恒空，复制错误（如 1133）看不见。
- **功能目标（验收标准）**
  1. 三形态（MySQL docker / MariaDB 裸机 / MariaDB 容器）**错误日志均可读取**
  2. 三形态**慢日志**（`mysql.slow_log`）均可采集
  3. 读不到时 UI **明确提示原因**（权限 / 路径 / 配置项），不静默空白
- **涉及模块**：`app/api.py`（错误日志 / 慢日志接口）、`app/node_gen.py`（配置渲染）、前端
