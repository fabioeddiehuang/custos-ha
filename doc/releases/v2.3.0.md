# v2.3.0 — MariaDB 版本准绳与变更生效闭环

```
状态：已实现（待部署验证）
目标版本：v2.3.0
上一版本：v2.2.20
规划日期：2026-09-10
发布日期：（部署验证后填）
```

## 一、版本定位

2.3.x 是「**MariaDB 12.3.3 主线**」阶段的第一个版本。本版不加炫功能，只补两件
每天都在影响运维正确性的地基：

1. **版本有准绳** —— 明确支持哪些 MariaDB 版本，授权不再靠「猜版本号 + 吞异常」。
2. **变更有回声** —— 在 Web 上改了任何配置，必须明确告诉运维「去节点上做什么」，
   并区分「重启即可 / 必须重建容器 / 要执行 SQL」，杜绝「改了没生效也不知道」。

同时执行 **MySQL 8.0 冻结策略**：本版所有改动不得进入 MySQL 分支，
共享代码路径（`mysql_compat`、`config_drift`、`monitor`）的改动须保证 MySQL 行为不变。

## 二、功能规划

### F1. MariaDB 版本支持矩阵与版本感知 `P0`

- **功能目的（Why）**
  - v2.2 对 MariaDB 只有「是 / 不是 MariaDB」一层判定，**没有版本概念**：
    - ha_monitor 授权串在 `node_gen`（有 `REPLICATION MASTER ADMIN`）与
      `ha_client`（没有）**各写一份且不一致**；
    - `ensure_ha_creds` 的补授循环对 4 个特权名**无条件 GRANT**，靠 `except` 吞错，
      在不支持的版本上刷 1064/1227 且**完全静默**；
    - 没有任何「这个版本受不受支持」的判断，节点跑 10.6 还是 12.3 全靠人肉记。
- **功能目标（验收标准）**
  1. 新增 `app/mariadb_matrix.py`：单一支持矩阵（最低 10.6 / 主线 12.3 / 兼容 10.6·10.11 /
     支持 11.4·11.8·12.x），提供 `support_check()` 与 `matrix_rows()`
  2. **授权改为能力探测**：运行期用 `SHOW PRIVILEGES` 过滤特权名，
     不存在的特权直接跳过（不再靠吞异常）；4 处授权串收敛为 1 处常量
  3. 预检新增「版本准入」项：低于最低支持线报 ERR，兼容/支持版本给 INFO 与升级建议
  4. 节点真实版本（连库探测）自动回写 `nodes.mysql_version`，不再依赖手填
- **涉及模块**：新增 `app/mariadb_matrix.py`；改 `app/ha_client.py`、`app/node_gen.py`、
  `app/precheck.py`、`app/api.py`
- **依赖**：无
- **非目标**：不做版本**升级编排**（→ v3.0-F3）；不因版本差异切换复制语法
  （MariaDB 全系列统一 `MASTER_USE_GTID=slave_pos`）

### F2. 变更生效提示：重启 / 重建容器 / 执行 SQL `P0`

- **功能目的（Why）**
  - 现状：Web 上改半同步、改 VIP、重新生成节点文件后，页面只说「已重新生成」，
    **不说接下来要做什么**。运维不知道该 `restart` 还是必须 `--force-recreate`：
    - my.cnf 里的**静态参数**（`plugin_load_add`、`server_id`、`innodb_buffer_pool_size`、
      `log_bin` 等）改了，只 `restart` 容器**根本不会生效**，必须重建容器；
    - keepalived.conf / ha_check.conf 改了只需 `restart keepalived`；
    - init SQL **只在数据目录为空的首次启动执行**，已初始化的实例改了它毫无效果。
  - 结果是「以为改了，其实没生效」，且排障时无从下手（v2.2 的 keepalived 探活超时
    修复就卡在这：存量节点必须 regen + 手动同步 + restart，但页面从未提示）。
- **功能目标（验收标准）**
  1. 重新生成节点文件时**自动 diff 新旧内容**，产出「需要在节点上执行的动作清单」
  2. 动作分四级并给出**可直接复制的命令**：
     - `recreate` —— 必须重建容器才生效（数据库配置/镜像变更）
     - `restart` —— 重启对应服务即可（keepalived / node-agent）
     - `exec` —— 需在节点本机执行一次（prepare-logs.sh、fix-node-creds.sql）
     - `manual` —— 需人工确认（首次部署、init SQL 只对空数据目录生效）
  3. 节点列表 / 集群页显示「**配置待生效**」徽标，点开可见清单与命令
  4. 运维在节点执行完可点「**已执行**」清零；未清零的持续提示，不会自己消失
- **涉及模块**：`app/node_gen.py`（diff + 动作映射）、`app/db.py`（新增列）、
  `app/api.py`（regen 返回动作 / 查询 / 确认接口）、`app/templates/nodes.html`
- **依赖**：无
- **非目标**：不做远程执行（不引入 SSH / agent 下发），只做「提示 + 命令」
  （远程下发 → v2.5 单元分发）

### F3. MariaDB 侧半同步变量命名一致性 `P1`

- **功能目的（Why）**：MariaDB 全系列沿用 `rpl_semi_sync_master/slave` 命名
  （11.5+ 才有 source/replica 别名），代码里此前没有任何说明，后续极易被
  「照 MySQL 改成 source/replica」的改动误伤，导致节点启动即崩。
- **功能目标**：半同步变量/插件名由 `mariadb_matrix` 单一来源提供并加注释说明，
  `node_gen` 改为引用它；行为**完全不变**（仍为 master/slave）。
- **非目标**：不切换命名体系。

## 四、变更记录

### 新增功能（Added）

- **MariaDB 版本支持矩阵**（`app/mariadb_matrix.py`）：
  主线 12.3.3；支持 11.4 / 11.8 / 12.0~12.2；兼容 10.6 / 10.11；<10.6 不支持。
  提供 `support_check()`（预检准入）与 `matrix_rows()`（文档/前端展示）。
- **预检新增「版本准入」项**：低于最低支持线报 `ERR`，兼容系列给 `WARN` 与升级建议。
- **版本自动登记**：`POST /api/node_detail` 连库取 `SELECT VERSION()` 并回写
  `nodes.mysql_version`（原为手填字段，常年空/过期）；同时返回 `version_support`。
- **变更生效提示**（F2）：重新生成节点文件时 diff 新旧内容，产出动作清单，分四级
  `recreate`（必须重建容器）/ `restart`（重启服务）/ `exec`（节点执行一次）/ `manual`（人工确认），
  每项给出**可直接复制的命令**与「为什么必须这么做」的说明。
- **节点列表「配置待生效」徽标**：点击弹出动作清单；执行完点「已在节点执行」清除提示。
- 新增接口：`GET /api/nodes/{ip}/pending`、`POST /nodes/{ip}/ack_deploy`。
- 新增字段（`nodes` 表，启动时自动迁移）：`gen_fingerprint`、`pending_actions`、`pending_since`。
- README 新增「3.1 数据库版本支持矩阵」章节。

### 改进（Changed）

- **授权串收敛为单一来源**：`node_gen`（init SQL / fix-node-creds.sql）与
  `ha_client.ensure_ha_creds` 四处权限集统一改为引用 `mariadb_matrix`，
  消除「node_gen 有 `REPLICATION MASTER ADMIN`、ha_client 没有」的长期不一致。
- **特权按能力探测**：运行期用 `SHOW PRIVILEGES` 过滤特权名，服务器不支持的直接跳过，
  不再对 4 个特权名无条件 GRANT 后用 `except` 静默吞掉 1064/1227。
  MySQL 分支保持原列表与行为不变（探测失败时不过滤，兜底逻辑不变）。
- **半同步插件名**改由 `mariadb_matrix.semisync_plugin_load()` 提供，并写明
  「MariaDB 全系列沿用 master/slave 命名、切勿照 MySQL 改成 source/replica」的注释。
- `nodes.mysql_version` 由 `varchar(16)` 扩容为 `varchar(48)`
  （MariaDB 完整版本串如 `10.6.21-MariaDB-log` 达 19 字符，原长度会被截断）。

### 修复（Fixed）

- **问题现象**：MariaDB 节点上 ha_monitor 的授权在「init 建号」与「自愈补号」两条路径上不一致，
  且补授循环对不存在的特权名刷 1064/1227 后被静默吞掉，排障时完全看不到。
  **根因**：权限集被复制成两份并各自维护，且无版本/能力判定。
  **修复方式**：统一为 `mariadb_matrix` 单一来源 + `SHOW PRIVILEGES` 能力过滤。
  **影响面**：仅 MariaDB 路径；MySQL 8.0 授权逻辑一行未动。
- **问题现象**：改配置/regen 后页面只说「已重新生成」，不说要在节点做什么，
  导致 my.cnf 静态参数改了只 restart 容器**根本不生效**，而运维以为已生效。
  **根因**：缺少「变更 → 生效方式」的映射与提示。
  **修复方式**：regen 时 diff 生成文件并按规则表映射为带命令的动作清单，入库并在列表页提示。
  **影响面**：三种节点形态全部覆盖；不影响任何运行时行为（仅提示，不远程执行）。

### 已知问题（Known Issues）

- 变更生效提示**只提示不下发**：不会远程执行任何命令（远程下发属 v2.5 单元分发）。
- 「已执行」需运维手动点击；若 regen 后配置再次变化（指纹变），待办会重新出现（符合预期）。
- 版本支持矩阵中未列出的**更高**系列（如未来 13.x）按 `supported` 处理，
  属有意设计（向前兼容），不因矩阵未更新而误判为不支持。
