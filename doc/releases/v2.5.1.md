```
状态：已发布
目标版本：v2.5.1

发布日期：2026-10-05
```

## 一、版本定位

v2.5.0 的功能补丁版，**不含新功能**，集中修复一批实测 / 运行期必炸点与稳定性隐患：
管理库历史表无限增长、引导 token 验签 403、若干 Web 接口 422/500、配置漂移巡检并发误判、
节点 compose 启动参数可读性。

所有修复已在真实 `custos-server` 与隔离实例验证 / 部署。

## 二、变更明细

### 1. 管理库历史表无限增长治理（防磁盘撑满 / 巡检查询变慢）
- monitor: 新增 `_purge_stale_data()`，每日清理 `agent_commands`(7d,仅终态) / `alerts`(90d,仅闭环) / `switch_history`(365d) / `audit_log`(365d)，`run_forever` 调用，异常降级不中断巡检
- agent_hub: 新增 `purge_old(days=7)`，物理删除 `agent_commands` 终态 (done/failed/expired) 记录
- monitor: `_collect_due` 改用 `dict.get` 防 `_COLLECT_CYCLE` 缺键 KeyError

### 2. 功能缺陷修复
- api: backup/policy 保存 `enabled` 由 `int`→`bool(Form)`，兼容前端 `URLSearchParams` 的 `"true"`，修复 422
- api: `config_drift/remediate` 的 `cluster_id` 由 int 默认参数→`Form(0)`，修复前端 POST body 参数被当 query 默认 0 导致「永远无漂移项」
- config_drift: `check_cluster` 整批原子提交（get_conn + 显式 commit），避免 monitor 巡检与 remediate 并发时读到半批 → 误判无漂移
- db: `reset_repl_password` 对 `get_current_master` 返回的 `(host,port)` 元组做健壮解包（dict/列表/元组兼容），修复 cred_reset_repl 500

### 3. bootstrap token 时区耦合修复（所有引导 token 永远 403）
- db: `bootstrap_tokens` 新增 `expires_ts(BIGINT)` 列，`init_schema` 兼容旧库 ALTER 补列
- bootstrap: `issue_token` 落库原始纪元秒 `expires_ts`；`verify_token` 优先用 `expires_ts` 验签，缺失回退旧 DATETIME 路径，彻底解耦「管理库会话时区 vs 管理端进程时区」不一致导致的整小时偏差

### 4. 节点 compose 启动参数可读性优化
- node_gen: MySQL command / init-logs entrypoint / MariaDB entrypoint / agent command 的多段 block 列表改为单行流式数组（exec 语义不变，避免误改成字符串造成双 mysqld / sh -c 破坏 SIGTERM 优雅关闭）

## 三、升级方式
与 v2.5.0 完全一致：升 `.env` 的 `VERSION=v2.5.1` 后，`./scripts/deploy.sh up -d --build`（重建管理器镜像）；节点侧无需升级（纯 bug 修复，节点 agent 版本同步为 2.5.1，向后兼容）。
