## 一、版本定位

> 修掉三轮验收里"反复出现、始终没根治"的三类问题：备份恢复（性能/日志/进度）、
> MariaDB 日志读不到、集群管理页卡片 UI。

## 二、功能规划

### F1. 备份恢复体验闭环 `P0`

- **功能目的（Why）**
  - (a) MySQL 恢复耗时远高于数据量更大的 MariaDB，用户感知为"恢复有问题"；
  - (b) 备份页「操作日志」页签恒为空，无法追溯备份/恢复成败；
  - (c) 恢复期间前端只有一个「恢复中…」按钮，长恢复被误认为卡死。
- **功能目标（What / 验收标准）**
  1. MySQL 恢复耗时较 2.3.5 明显下降；
  2. 「操作日志」能看到每次备份/恢复的时间、节点、范围、成功/失败条数；
  3. 恢复过程有进度条 + 阶段文案 + 已用时长，可后台运行，刷新页面自动接管。
- **涉及模块**：`app/backup.py`、`app/api.py`、`app/templates/backup.html`
- **非目标**：不做恢复断点续传；不做磁盘级物理备份（仍为逻辑备份）。

### F2. MariaDB 错误/启动日志可读 `P0`

- **功能目的（Why）**
  - MariaDB 没有 `mysql.error_log` 表；退路 `LOAD_FILE(@@log_error)` 又因
    mysqld 生成的 `error.log` 为 **0660** 权限而**恒返回 NULL**（实测 660→NULL、
    644→有内容），且受 `secure_file_priv` 限制 → 面板永远空。
- **功能目标（What / 验收标准）**
  1. MariaDB 节点的错误日志、启动日志均能正常显示；
  2. 面板「来源」明示命中哪一级（表 / 文件 / 节点 agent）；
  3. 时间戳按各自口径正确换算（MySQL=UTC→+08:00；MariaDB=本地时间）。
- **涉及模块**：`scripts/node_agent.py`、`app/os_metrics.py`、`app/api.py`
- **依赖**：需节点侧重启 `custos-node-agent` 才能用上新接口。
- **非目标**：不做日志实时推送（仍为按需拉取）。

### F3. 日志筛选与集群卡片 UI `P1`

- **功能目的（Why）**
  - 日志页 Error/Warn/Info 筛选按钮**没有任何 CSS**，渲染成浏览器默认外观，与全站不一致；
  - 集群管理页卡片在 `auto-fill` 下不撑满宽度，且 4 个按钮折成两行。
- **功能目标（What / 验收标准）**
  1. 筛选按钮与全站胶囊标签风格一致，筛选生效；
  2. 卡片自适应撑满整行，4 个按钮同一行，两卡片观感协调。
- **涉及模块**：`app/static/v3.css`、`app/templates/cluster_detail.html`、`app/templates/clusters.html`

## 四、变更记录（发版时填写）

### 新增功能（Added）

- 恢复进度：`POST /api/backup/restore` 改为**后台任务**并返回 `task_id`；
  新增 `GET /api/backup/restore_progress?task_id=|cluster_id=`；备份页新增进度弹窗
  （进度条 + 阶段 + 已用时长，支持「后台运行」，刷新页面自动接管未完成任务）。
- 新增 `GET /api/backup/log?cluster_id=&limit=`（备份/恢复操作日志）。
- 节点 agent 新增只读接口 `GET /logs?name=error&lines=N[&path=]`；管理器新增
  `os_metrics.fetch_node_log()`。

### 改进（Changed）

- 错误日志读取升级为**三级**：`mysql.error_log` 表（仅 MySQL 8.0）→ `LOAD_FILE` →
  **节点 agent 直读宿主机文件**（新增，绕开 FILE 权限 / `secure_file_priv` / 0660 权限）。
- 前端「来源」标签显示实际命中的读取级别（表 / 文件 / 节点 agent）。
- 集群卡片：`.cc-grid` 由 `auto-fill` 改 `auto-fit`（空轨道折叠、卡片撑满宽度）；
  `.cc-foot` 改 `nowrap` + 按钮等比收缩，4 个按钮不再折行；「修改配置/密码」文案缩为
  「配置/密码」（`title` 保留全称）。
- 补全 `.log-filter` / `.lvl-btn` 样式，与全站胶囊标签统一。

### 修复（Fixed）

- **MySQL 恢复远慢于 MariaDB** → 根因：dump 头 `SET AUTOCOMMIT=0` 使**整个恢复成为
  一个超长事务**，MySQL 8.0 对长事务（undo/history 膨胀、redo checkpoint 推迟）极不友好
  → 修复：每 `1000` 条语句提交一次（`_RESTORE_COMMIT_EVERY`）；恢复本非原子操作，语义不变。
- **备份「操作日志」恒为空** → 根因：`_log_event()` / `read_backup_log()` 定义了
  **从未被调用**，`/api/backup/log` 端点不存在，备份页路由也未传 `blog`
  → 修复：在 `run_backup` / 恢复任务埋点；新增端点；路由传 `blog=`；
  `read_backup_log` 过滤改为边界匹配 `(^|\s)id=N(\s|$)`（防 `id=1` 误命中 `id=11`）。
- **MariaDB 错误/启动日志恒为空** → 根因见 F2 → 修复：新增节点 agent 直读通道。
- **MariaDB 日志时间戳解析失败 / 时区错位** → 根因：MariaDB 用空格分隔且小时可能只有
  1 位（`2026-09-11  9:15:32`），且为**本地时间**，与 MySQL 的 `T` 分隔 UTC 不同
  → 修复：`_ERR_TS_RE` 兼容三种格式；`_err_ts_to_cn` 按来源区分时区口径。
- **日志筛选按钮 UI 与全站不一致** → 根因：`.lvl-btn` 无任何 CSS → 修复：补齐样式。
- **集群卡片宽度不协调 / 按钮折行** → 见「改进」。
- **审计页字段错配** → 根因：`audit.html` 读 `node/username/operation/details`，
  而 `audit_log` 表字段为 `actor/action/target/detail`，Jinja 取不到值渲染为空
  → 修复：改用正确字段 + 中文动作映射（表格列：时间/用户/操作/对象/详情）。
- `backup.html` 的 `loadLog()` 在 `catch` 中引用了作用域外的 `el`（会抛
  ReferenceError）→ 修复。

### 已知问题（Known Issues）

- 顶部导航没有审计入口，`/audit` 仅能直接访问（是否加入菜单待定）。
- 恢复进度仅在管理器进程内存中，管理器重启后进度丢失（恢复本身也会随进程终止而中断）。
- 读取 MariaDB 日志依赖 `custos-node-agent` 在线；agent 未升级/未运行时回退到前两级。
