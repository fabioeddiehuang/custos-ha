# Custos HA · 数据库字段说明

> 适用版本：**v2.2.20**（与 `.env` 的 `VERSION` 一致）
> 管理库为独立的外部 MySQL/MariaDB（默认库名 `ha`，utf8mb4）。表结构由 `app/db.py` 的 `SCHEMA_SQL` 与 `init_schema()` 创建/迁移。
> 管理端通过 `db.py` 的 `query()` / `execute()` 每次获取**新连接**（避免多线程共享 PyMySQL 连接导致协议错乱）。

---

## 1. 总览

| 表名 | 作用 | 关键外键/关联 |
|------|------|---------------|
| `hosts` | 被管节点实时/最近状态快照 | `cluster_id` → `clusters.id` |
| `current_master` | 各集群当前主库（防脑裂仲裁源） | `cluster_id` 主键 |
| `switch_history` | 切换历史（from→to + 原因） | `cluster_id` |
| `clusters` | 集群配置（VIP/账号/网卡） | 主键 `id` |
| `nodes` | 节点部署单元元信息（IP/端口/密码/类型） | `cluster_id` → `clusters.id` |
| `users` | Web 登录账号 | `username` 唯一 |
| `settings` | 键值配置（开关/保留期等） | `key` 主键 |
| `alert_emails` | 告警收件邮箱 | `id` 主键 |
| `alert_email_map` | 邮箱↔集群路由 | `(email_id, cluster_id)` 主键 |
| `alerts` | 告警/自愈状态记录 | `cluster_id` |
| `metric_history` | 指标周期快照（趋势图） | `cluster_id, host, port` |
| `slow_log` | 慢日志采集结果 | `cluster_id, host, port` |
| `slow_log_cursor` | 慢日志增量采集游标 | `(cluster_id, host, port)` 主键 |
| `config_drift` | 跨节点配置一致性巡检 | `cluster_id` |
| `audit_log` | 操作审计日志 | `cluster_id` |

## 2. 逐表字段

### 2.1 hosts（节点状态快照）
由监控线程周期性写入，前端仪表盘/集群卡片直接读取。

| 字段 | 类型 | 为空 | 说明 |
|------|------|------|------|
| `id` | INT AUTO_INCREMENT | 否 | 主键 |
| `host` | VARCHAR(64) | 否 | 节点 IP |
| `port` | INT | 否 | 节点 MySQL 端口（docker MySQL 默认 3307，MariaDB 默认 3306） |
| `role` | VARCHAR(16) | 可 | 角色：`master` / `slave` / `unknown`（探活得出） |
| `server_id` | BIGINT | 可 | MySQL `server_id` |
| `status` | VARCHAR(8) | 可 | `up` / `down` / `unknown` |
| `is_current_master` | TINYINT(1) | 可 | 是否为集群当前主库（0/1） |
| `initial_role` | VARCHAR(8) | 可 | 节点生成时指定的初始角色（默认 `slave`），用于首次部署引导 |
| `err` | TEXT | 可 | 探活失败原因（便于前端展示，如账号错误/网络不可达） |
| `repl_delay` | INT | 可 | 复制延迟（秒），NULL 表示非从库/未知 |
| `slave_io` | VARCHAR(16) | 可 | IO 线程状态：`Yes` / `No` / `Connecting` |
| `slave_sql` | VARCHAR(16) | 可 | SQL 线程状态：`Yes` / `No` |
| `last_seen` | DATETIME | 可 | 最近一次成功探活时间（按 `HEARTBEAT_INTERVAL` 限频写入，设 0 不写） |
| `cluster_id` | INT | 可 | 所属集群（`clusters.id`） |
| 唯一键 | `uq_host (host, port)` | — | 同 IP:端口唯一 |

### 2.2 current_master（当前主库仲裁）
keepalived 检查脚本 + 管理器共同读取，作为 VIP 归属与防脑裂依据。

| 字段 | 类型 | 说明 |
|------|------|------|
| `cluster_id` | INT | 主键，按集群隔离 |
| `host` | VARCHAR(64) | 当前主库 IP |
| `port` | INT | 当前主库端口 |
| `updated_at` | DATETIME | 更新时间（变更即刷新） |

### 2.3 switch_history（切换历史）
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT AUTO_INCREMENT | 主键 |
| `from_host` / `from_port` | VARCHAR(64) / INT | 切换前主库 |
| `to_host` / `to_port` | VARCHAR(64) / INT | 切换后主库 |
| `reason` | VARCHAR(255) | 切换原因（如 `master down`、`manual`） |
| `cluster_id` | INT | 所属集群（迁移新增） |
| `created_at` | DATETIME | 切换发生时间 |

### 2.4 clusters（集群配置）
「集群管理」页维护，每个集群独立的 VIP / 账号 / 网卡。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(64) | 集群名称 |
| `ha_user` / `ha_pass` | VARCHAR(64) / VARCHAR(255) | HA 监控账号（`ha_monitor`）及密码 |
| `repl_user` / `repl_pass` | VARCHAR(64) / VARCHAR(255) | 复制账号（`replication`）及密码 |
| `app_user` / `app_pass` | VARCHAR(64) / VARCHAR(255) | 业务账号（`app`）及密码 |
| `vip` | VARCHAR(45) | 虚拟 IP（同网段空闲地址） |
| `vip_prefix` | VARCHAR(4) | 掩码位（默认 `24`） |
| `interface` | VARCHAR(32) | VRRP 广播网卡（如 `eth0`） |
| `vrid` | VARCHAR(8) | 虚拟路由 ID（同网段内唯一） |
| `vip_port` | INT | VIP 对外访问端口（默认 `3307`，业务连 `VIP:VIP_PORT` 访问主库） |
| `node_type` | VARCHAR(16) | 集群节点部署类型：`docker`（容器化 MySQL 8.0，默认）/ `mariadb-docker`（容器化 MariaDB 12.3.x，纯 compose）/ `mariadb`（裸机 MariaDB 12.x） |
| `mysql_version` | VARCHAR(16) | MySQL 大版本（如 `8.0` / `12.3`）；NULL 表示沿用旧复制语法。决定复制语法分支（MySQL 8.0 ↔ MariaDB） |
| `created_at` | DATETIME | 创建时间 |

> **同集群须同「引擎族」**：`mariadb` 与 `mariadb-docker` 可混部（同为 MariaDB GTID）；**MySQL 与 MariaDB 禁止混部**。判风味以 `detect_flavour()`（`SELECT VERSION()`）为准。

### 2.5 nodes（节点部署单元元信息）
Web「节点配置」添加时写入；密码用于 manager 远程自愈/终端回退。

| 字段 | 类型 | 说明 |
|------|------|------|
| `ip` | VARCHAR(64) | 主键，节点 IP |
| `port` | INT | 节点 MySQL 端口 |
| `root_user` | VARCHAR(64) | 节点 root 账号（默认 `root`） |
| `root_pass` | VARCHAR(255) | 节点 root 密码（容器创建时固定，不随 HA_PASS 漂移；用于 ha_monitor 凭证自愈与切换的 root 回退） |
| `server_id` | INT | 节点 `server_id` |
| `compose_path` | VARCHAR(255) | 生成目录在宿主机的显示路径（`NODES_HOST_BASE/<ip>`） |
| `cluster_id` | INT | 所属集群（`clusters.id`） |
| `node_type` | VARCHAR(16) | 同上三种：`docker`（默认）/ `mariadb-docker` / `mariadb` |
| `mysql_version` | VARCHAR(16) | MySQL 大版本；NULL 沿用旧语法 |
| `created_at` | DATETIME | 创建时间 |

### 2.7 settings（键值配置）

| 字段 | 类型 | 说明 |

**常见 key**：`AUTO_FAILOVER`、`AUTO_REPAIR`、`ALERT_COOLDOWN_SEC`、`ALERT_MERGE`、`ALERT_LAG_THRESHOLD`、`ALERT_RECEIVERS`、`SLOWLOG_ENABLED`、`LAG_FAILOVER_ENABLED`、`LAG_FAILOVER_SEC`、`LAG_FAILOVER_CYCLES`、`PRESSURE_FAILOVER_ENABLED`、`PRESSURE_THREADS_RUNNING`、`PRESSURE_ROW_LOCK_WAITS`、`FAILOVER_COOLDOWN_SEC`、`METRIC_RETENTION_DAYS`(30)、`SLOWLOG_RETENTION_DAYS`(7)、`CLUSTER_NAME`、`HA_USER`、`HA_PASS`、`REPL_USER`、`REPL_PASS`、`APP_USER`、`APP_PASS`、`VIP`、`VIP_PREFIX`、`INTERFACE`、`VRID`（旧版兼容，新版本已迁入 `clusters`）。

## 3. 关键关系与说明

- **集群隔离**：`hosts` / `nodes` / `current_master` / `switch_history` / `metric_history` / `slow_log` / `config_drift` / `alerts` / `audit_log` 均带 `cluster_id`，所有监控、切换、告警、清理按集群隔离。
- **凭证来源**：集群级账号（`ha_monitor`/`replication`/`app`）存于 `clusters`；节点 root 密码存于 `nodes`。管理器对在线节点周期性执行凭证自愈（`ensure_ha_creds`），优先 `ha_monitor` 校正，缺权限则回退 `root`。
- **空闲零写入**：`hosts.last_seen`、指标/漂移快照、拓扑收敛均做「变更前比对」，值未变不落库，避免稳态下持续写盘。
- **迁移兼容**：`init_schema()` 含大量 `ALTER TABLE ... ADD COLUMN` 容错分支与默认集群迁移（旧 `settings` 凭证 → `clusters` 首行），升级时自动补齐，无需手工建表。
