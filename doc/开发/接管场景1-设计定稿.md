# 集群接管 · 场景 1「旧库单机 → 建集群容灾」设计定稿

> 日期：2026-10-01 ｜ 版本：v2.5.0 ｜ 状态：**设计定稿，待确认后实施（未写业务代码）**
> 配套：`doc/开发/v2.4.1-接管设计.md`（背景）、`test/adopt-demo.html`（交互 demo，样式与流程以此为准）

---

## 1. 范围与原则

- **只做场景 1**：一台正在跑的旧库（无复制）→ 纳管为**单节点集群** → 后续用户**手动加从库**获主从 + VIP 漂移。
- 场景 2（现成主从集群接管 VIP+切换）**本次不做**。
- **原则**：接管 = 纳管，不是重建。接管阶段**只装 sidecar（keepalived+agent）**，不重装数据库、不碰数据、不重建复制。

### 与旧设计的关键差异
| 旧 | 本设计 |
|---|---|
| 扩从库(extend)捆进向导 | 扩从库**移出向导**，作为接管后独立动作（复用现有加节点流程） |
| 单机可接入已有节点的集群 | **只新建集群**（避免撞角色/误建复制，BUG-006 根因） |
| 探测只覆盖版本/binlog/server_id | 增加 `read_only`、仍是从库、`bind_address`、数据量、部署形态识别 |

## 2. 流程

```
① 添加旧库 → ② 版本校验与探测(只读) → ③ 创建集群 → ④ 执行挂载 → ⑤ 后续：手动加从库
                   ↓ 阻断项未清零则不放行
```

- ② 的「开始探测」与「重新探测」**同一行**；未探测时结果区显示占位提示。
- ③④ 底部常驻 `上一步/下一步`（④ 为末步，隐藏"下一步"）。

## 3. 步骤要点

**① 添加旧库**：`ip/port/user/pass`（管理员账号，用于建 ha_monitor）。文案强调只读、不重启、不改 my.cnf。

**② 版本校验与探测**：输出版本结论 + 复制能力表 + 部署形态 + 数据量 + 修复命令（裸机/容器双支线）。**必须已探测**才进 ③；**任一阻断项未清零不放行**。

**③ 创建集群** 字段（`create_cluster` 契约）：

| 字段 | 默认 | 说明 |
|---|---|---|
| 集群名称 | 必填 | — |
| VIP | 前缀自动(旧库 IP 前 3 段)+末段输入 | §5 占用检测 |
| VIP 端口 | **= 旧库探测端口** | §4 关键约束 |
| 网卡 `interface` | `eth0`（兜底） | 实际由 keepalived entrypoint 自动探测校正 |
| VRID | 自动推荐空闲值，可改 | 1–255，§5 同网段查重 |
| server_id | 留空=`get_next_server_id()` | 可自填 1–4294967295 |
| ha/repl/app 账号密码 | **自动 `rand_secret(16)`** | 折叠「高级：自定义」可改 |
| `node_type` | 自动：裸机→`mariadb`；容器→`mariadb-docker` | 由 ② 形态识别决定 |
| `mysql_version` | 自动=探测版本 | 供后续加从库匹配 |

**④ 执行挂载**：建 `ha_monitor` 账号 → 登记 → 生成 sidecar 引导命令（`sidecar_only`）。结果区展示账号密码（明文一次+复制，留空自动生成）、引导命令、**agent 心跳**。引导脚本内嵌：环境预检 → **节点本机 arping 校验 VIP 空闲**（冲突即中止）→ 装 sidecar。

执行成功后出现 **「完成」按钮** → 点击**跳转集群管理页 `/clusters`**（新集群已出现在列表中）。

### ④ 附：Docker 预检的确切行为（**不自动安装 Docker**）

引导脚本（`bootstrap.py:513-520`）现有预检：

```bash
# 1) 环境检查：本期仅支持 docker 环境（无 docker 节点的安装留后续版本）
[ "$(id -u)" = "0" ] || die "请用 root 执行（sudo bash）"
command -v docker >/dev/null 2>&1 || die "未检测到 docker。本版本仅支持已安装 docker 的节点。"
docker compose version  >/dev/null 2>&1 || die "未检测到 docker compose（v2 插件）。"
# 2) 磁盘空间预检（阈值 5GB，与 preflight.py 一致）
```

**结论：检测到没有 Docker 时直接 `die` 报错退出，不会自动下载/安装 Docker**（脚本注释明写"无 docker 节点的安装留后续版本"）。

**本次设计决定（用户已确认：保持现状，绝不安装 docker）：保持"不自动安装"，预检失败时阻断 + 给指引，不做任何 docker 下载/安装动作。** 理由：
1. Docker 安装是重量级系统变更（装包、启 daemon、影响网络），在**正在跑业务的旧库主机**上自动装违反"接管不搞坏旧库"第一原则。
2. 安装方式随发行版而异（apt / yum / dnf）且受软件源影响，自动适配易失败、失败后状态更难收拾。
3. 真正的免 Docker 方案是**下一版的二进制可执行文件形态**，本期不必为此自动装 Docker。

落地（本次新增）：预检失败时给出**明确阻断 + 可复制的安装指引**（按发行版给命令，附国内源），并说明"安装后重新执行同一条引导命令即可——引导脚本幂等，可重复执行"。

**⑤ 后续手动加从库**：集群页 → 加从库节点（Custos 拉起同版本实例 + `make_slave_of`）。版本按集群 `mysql_version` 匹配。

## 4. 关键约束（易踩坑，必守）

1. **VIP 端口 = 旧库实际端口**。容器形态 compose 有端口映射，但**裸机形态没有**——keepalived 只漂 IP，不做端口转换。VIP 端口若 ≠ 旧库监听端口，业务连不上。（现有默认值 3307 仅作为容器形态默认，接管场景必须以探测端口为准。）
2. **`bind_address` 必须为 `0.0.0.0` / `*`**。Custos 自建节点强制 `0.0.0.0`（node_gen.py:618/690/957），但旧库不受控；若绑 127.0.0.1 或单 IP，**VIP 漂移后连不上**。→ 设阻断，写 `bind-address=0.0.0.0` 进 `99-custos-adopt.cnf`。
3. **VRRP 用 IP 协议号 112**（非 TCP/UDP），旧库主机/网络须放行，否则漂移失败且现象诡异（双主或都不上浮）。引导脚本预检 + 页面提示。
4. **配置改动只新增 `99-custos-adopt.cnf`**，绝不改旧库现有 my.cnf；动手先 `cp -a` 备份。
5. **`log_bin` 是只读变量，SQL 改不了**，必须写配置 + 重启 → 一律给命令，绝不假装改成功。

## 5. 探测项与阻断判定表

| 检测项 | 取值 | 级别 | 自动修复 | 修复方式 |
|---|---|---|---|---|
| 版本支持 | `VERSION()` + version_profile | **阻断** | 否 | 不支持即拦（EOL 版本提示） |
| 连通性 | connect | **阻断** | 否 | 查 IP/端口/口令 |
| `read_only`/`super_read_only` | `@@read_only` | **阻断** | **是**（仅 role=standalone） | 在线 `SET GLOBAL read_only=0; super_read_only=0;`（供建账号）+ 写 cnf `read_only=0` 持久化 |
| 仍是别人从库 | role=slave / `SHOW REPLICA STATUS` | **阻断** | **否** | 展示 Master_Host + `STOP REPLICA; RESET REPLICA ALL;` + **二次确认**（不可逆业务决策） |
| `log_bin` | `@@log_bin` | **阻断** | 否(需重启) | cnf `log_bin=mysql-bin` |
| `gtid_strict_mode` | `@@gtid_strict_mode` | **阻断** | 否(需重启) | cnf `gtid_strict_mode=ON` |
| `binlog_format` | `@@binlog_format` | 警告 | 否(需重启) | cnf `binlog_format=ROW` |
| `bind_address` | `@@bind_address` | **阻断** | 否(需重启) | cnf `bind-address=0.0.0.0` |
| `server_id` | `@@server_id` | 提示 | 留空自动分配 | cnf `server_id=N`（与 binlog 同一次重启生效） |
| 数据量 | `SUM(data_length+index_length)` 排除系统库 | 提示 | — | 仅展示；超时/无权限→降级"未知"，**不阻断** |
| 部署形态 | 用户确认/自动识别 | — | — | 决定修复命令支线与 `node_type` |

**修复命令双支线**（去掉具体 IP/面板字样，由形态决定）：
- 裸机：`printf` 写 `/etc/mysql/conf.d/99-custos-adopt.cnf` → `systemctl restart mariadb` → 验证。
- 容器：`docker exec <容器名>` 写**容器内**配置 → `docker restart` → 验证（客户端名兼容 `mariadb`/`mysql`）。

**其他检测**：
- **VIP 占用三层**：① 登记比对（`nodes.ip`/`clusters.vip`）→ **硬阻断**；② 管理器 ping → **警告**（禁 ICMP 者不通≠空闲）；③ **节点本机 arping**（装 keepalived 前）→ **冲突即中止安装**（防抢 IP 打瘫他人）。
- **VRID 查重**：以**旧主 IP 网段**（=VIP 网段）比对现有集群 VIP 同网段 + 同 vrid → 冲突报错并推荐空闲值；范围 1–255。

- 向导留空 → `create_cluster` 自动 `rand_secret(16)`；折叠「高级」可自定义；结果页明文展示一次。
- **事后修改走集群卡片「⚙ 修改配置/密码」**：保存即自动 `sync_node_creds`（改节点库账号）+ `regenerate_cluster_compose`（重渲染部署文件）。
- **本次增强（必须做）**：把 `update_cluster` 路径接上 **agent 自动推送**（`agent_hub.enqueue(ip,"update_files",{files,restart})`，能力已在 node_gen.py:1901，但该路径未调用）→ 推送到节点并自动 restart，做到**一键生效、用户无需任何人工操作**（现状需人工 scp + `docker compose restart`）。agent 离线时退回手工提示。
- `curl` 引导**只用于首次装 sidecar**；改密码不需要重装。

## 8. 加从库与进度展示改造

**现状问题**：`cluster_detail.html:925-954` 的重建进度是**前端动态浮层**（JS 创建 `position:fixed` 的 `#rebuildBar` + setInterval 轮询）→ **刷新页面即丢失**，用户体验差。且 `rebuild.py` 内**无百分比进度**（搜索 0 匹配）。

**改造（本次）**：
1. **改为集群详情页内联卡片**（非弹窗/非浮层），常驻显示。
2. **进度状态持久化在服务端**（task 表，如 `migration_tasks` 契约）；页面加载时主动查询该集群进行中任务并渲染 → **刷新不丢**。
3. **进度两段显示**（避免"100% 却还在追 binlog"的误导）：
   - `数据同步中 42.35%`（全量导入：已传输字节 ÷ ② 探测的数据量）
   - `追平中（延迟 Ns）` → `复制正常`
   - 字节级真实进度机制可复用 migration（`migration.py:515`、`api.py:3725-3727` 用 `size_mb` 作分母）。
4. **通用于 Custos 自建集群**：不区分接管/自建，加从库与重建从库统一走该卡片。
5. **导出参数（保留，不会被进度取代）**：用 `mariadb-dump --single-transaction`（单事务快照，不锁业务表）。项目已取消物理通道（`migration.py:244` 仅逻辑通道），故此参数必须保留；重建从库用同一套逻辑，是其另一调用方而非替代。

## 9. 撤销 / 回滚（最简）

只做"撤销登记"，三步：
1. 删除该节点 `nodes`/`hosts`/`current_master` 登记；
2. 删除管理器生成的节点部署目录（`generated_nodes/<ip>`）；
3. **不自动删旧库 ha_monitor 账号** → 页面给 `DROP USER` SQL + 复制按钮，由用户自决。

理由：删账号不可逆且有风险，交用户显式执行最安全；前两步纯管理器侧，不会出 bug。

## 12. 验收要点

- 未探测 / 有任一阻断项 → 无法进入 ③（硬门槛，无豁免）。
- read_only=ON 且 standalone → 自动解除并写配置；role=slave → 必须二次确认才继续。
- 修复命令按裸机/容器分别可执行（`log_bin` 重启后变 ON）。
- VIP 冲突 → 登记比对硬拦；arping 冲突 → 安装中止。
- 改密码 → 保存后 agent 自动推送生效，**无需人工**。
- 裸机下载 → 阿里云可达并按版本拼 URL。
- 加从库/重建 → 集群页内联卡片显示百分比，**刷新页面进度仍在**。
