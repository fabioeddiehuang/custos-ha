# Custos HA · 用户操作手册

> 适用版本：**v2.2.11**
> 定位：一套**以 MySQL/MariaDB 原生主从复制为底座、VIP + keepalived 提供单点访问**的高可用管理平台。支持**单管理端多集群**统一纳管，覆盖 Docker 容器与裸机两种部署形态。

---

## 1. 总体架构与三种部署形态

```
                         ┌─────────────────────────────┐
   浏览器 ──HTTP──▶       │  Custos 管理端 (manager)     │
                         │  · Web UI / API / 决策器     │
                         │  · 独立管理库 (外部 MySQL)    │
                         └──────────┬──────────────────┘
                                    │  TCP 3306/3307 探活 + 复制/凭证自愈
            ┌───────────────────────┼───────────────────────┐
            ▼                       ▼                        ▼
      [节点 A]                [节点 B]                 [节点 C]
   主库(VIP 归属)           从库(复制)              从库(复制)
   keepalived + MySQL      keepalived + MySQL       keepalived + MySQL
            └──────── VRRP 同一 VIP，主库漂移 ────────┘
```

**三类节点部署形态**（安装脚本不同，其余纳管逻辑一致）：

| 形态 | 安装脚本 | 典型端口 | 镜像/软件 | 适用场景 |
|------|----------|----------|-----------|----------|
| Docker MySQL 8.0 | `Install-mysql-docker-Node.sh` | 3307 | `mysql:8.0` | 标准 MySQL 8.0 容器化 |
| Docker MariaDB 12.3.x | `Install-mariadb-docker-Node.sh` | 3306 | `mariadb:12.3.x` | MariaDB 容器化（**注意 CPU 指令集预检**） |
| 裸机 MariaDB 12.x | `Install-ha-mariadb-Node.sh` | 3306 | 宿主机已装 MariaDB | 不希望容器化、直接复用宿主实例 |

> 形态差异仅体现在**部署/安装阶段**与 keepalived 容器名（`custos-node`）。管理端对三类节点**统一用 TCP 探活**，复制/切换/自愈逻辑通过 `mysql_version` 选择 MySQL 8.0 或 MariaDB 的复制语法（`CHANGE MASTER TO` ↔ `CHANGE REPLICATION SOURCE TO`）。

## 2. 首次部署（管理端）

1. 准备一台管理机（建议 ≥2 核 4G），安装 Docker，拉取管理器镜像 `custos:v2.2.11` 与 keepalived 镜像 `custos-node:v2.2.11`。
2. 准备一个**独立的外部 MySQL/MariaDB** 作为管理库（与业务库隔离）。
3. 用 `deploy.sh` 启动管理端（首次启动自动建表/迁移）：
   ```bash
   ./deploy.sh up -d
   ```
4. 浏览器访问 `http://<manager>:28888`，默认账号 `admin/admin`，首次登录请修改密码（设置 → 修改密码）。

---

## 3. 创建集群（集群管理）

进入「集群管理」→ 新建集群，填写：

- **集群名称**、**节点类型**（docker / baremetal）、**MySQL 大版本**（8.0 / 12.3，为空则沿用旧复制语法）
- **HA/复制/业务三类账号**与密码（平台自动在被管节点创建并周期自愈）
- **VIP**：与节点**同网段**的空闲地址（如 `192.168.1.20`）
- **掩码位**（默认 24）、**VRRP 网卡**（如 `eth0`）、**VRID**（同网段内唯一，避免与其它 keepalived 冲突）
- **VIP 端口**：业务连接 `VIP:VIP_PORT` 访问当前主库（默认 3307）

> 多集群互不影响；每集群独立的 VIP / 账号 / 告警路由。

---

## 4. 添加节点与安装（节点管理）

1. 「节点管理」→ 新增节点，填：集群、IP、端口、root 账号密码、server_id、节点类型/版本。
   - 系统做**同构校验**（版本/角色一致性），并**拦截把管理库地址当业务节点**的误配。
2. 保存后平台生成**自包含目录** `generated_nodes/<ip>/`，含 `docker-compose.yml`、`my.cnf`、安装脚本、凭证 SQL。
3. 把该目录整体拷到目标机 `/home/docker/<ip>/`（Docker 形态）或对应路径（裸机形态）。
4. **目标机执行安装**：
   - Docker：`cd /home/docker/<ip> && docker compose up -d`
   - 裸机：`sudo bash Install-ha-mariadb-Node.sh`
   - 安装脚本会：拉取/预检镜像 → 创建容器（host 网络，数据卷挂载）→ 初始化账号/GTID/复制参数 → 探活就绪。
5. 回到平台点「同步 / 拉取状态」，节点出现即纳入拓扑。

### Docker MariaDB 12.3.x 的 CPU 指令集注意事项
- `mariadb:12.3.3-ubi` 按 **x86-64-v3** 编译，老旧 CPU（如 QEMU 虚拟 CPU，仅支持到 v2）会直接 `Fatal glibc error: CPU does not support x86-64-v3` 秒退。
- 安装脚本内置**预检**：`docker run --rm --entrypoint mariadbd <img> --version` 失败即自动回退到**备用镜像 `mariadb:12.3.2`**（实测可在老 CPU 上运行）。两者皆失败才报错并提示改用裸机方案。
- **小内存机保护**：物理内存 < 3000MB 时，脚本自动把 `innodb_buffer_pool_size` 收敛为 `内存×40%`（≤512M），避免被 OOM 杀掉崩溃重启（亦可手动 `MARIA_BUFFER_POOL=512M` 覆盖）。

> 排查口诀：容器 `Up` 但脚本卡/报错，先看 `docker logs <容器>`——多数情况是 OOM 或旧数据目录损坏（清掉 `/data/mariadb/*` 重试）。

## 5. 日常监控与仪表盘

- 仪表盘按集群展示**健康卡片**（上下排列）：角色、状态、复制延迟、IO/SQL 线程、最后心跳，以及「设为主库 / 修复复制」快捷操作。
- 指标趋势、慢日志、`mysqld` 配置漂移巡检周期性采集；空闲态不重复落库。
- 拓扑页可视化主从关系与 VIP 归属。

---

## 6. 故障切换与复制修复

- **自动切换**：主库连续探活失败达阈值（`FAIL_THRESHOLD`）→ 决策器 `pick_best_master` 选最优从库 → 提升为主 → VIP 漂移（keepalived）→ 更新管理库 `current_master`（防脑裂仲裁）。
- **手动切换**：节点卡片「设为主库」→ `POST /api/failover/to` 指定提升目标。
- **复制中断修复**：「修复复制」→ `POST /api/heal`，平台重建复制通道、按错误类型做 GTID/位点自愈（IO 线程连接错误、SQL 线程位点冲突等分别处理）。
- **强制校正**：`POST /api/force` 用于 VIP/角色与实际不符时的兜底校正。
- 切换原因、前后主库记录在「切换历史」。

> 复制账号 `replication` 与 HA 账号 `ha_monitor` 由平台**周期自愈**；若节点 root 凭证变更，用「修正节点」(`/api/fix_node`) 更新，自愈将优先用 `ha_monitor`、缺权限回退 `root`。

---

## 7. 备份与恢复

「集群 → 备份恢复」：
- 列出可备份库 → 触发备份（落盘到管理端 `backups/` 卷）
- 支持预览、下载、恢复、删除
- 恢复指定库到指定节点

---

## 8. 告警中心

- 探活失败、配置漂移、复制延迟超阈值等会生成告警；可自愈的自动标记 `healed`，未恢复的标记 `unrecovered`。
- 收件邮箱支持「默认接收全部」与「按集群路由」两种。
- 告警支持确认/消音；可发测试邮件验证通道。

---

## 9. 在线终端、日志与设置

- **在线终端**：Web 里直接对节点执行 SQL（带账号回退：先 `ha_monitor`/业务账号，失败回退 `root`，再回退集群凭证）。
- **容器/管理器日志**：下拉动态列举本机可读取日志的容器，实时查看。
- **系统设置**：自动切换/自动修复开关、各类阈值（延迟、压力、连接数）、保留期（指标 30 天 / 慢日志 7 天）、邮件通道等。

## 10. 常见故障速查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 节点状态 `down` 且 `err` 为账号错误 | root 凭证变更 / 账号被删 | 「修正节点」更新凭证，平台自愈 |
| 从库 `Slave_IO_Running: Connecting` | 主库不可达 / 复制账号密码错 | 「修复复制」重建通道 |
| VIP 不漂移 | VRID 冲突 / keepalived 未起 / 网卡名错 | 检查 `vrid`、目标机 `docker ps`、网卡名 |
| Docker MariaDB 容器秒退 | CPU 指令集不满足 v3 | 脚本自动回退 12.3.2；仍不行则改裸机 |
| 容器 `Up` 但脚本报「未找到客户端」 | 旧版脚本 `command -v` 误用 | 升级安装脚本（v2.2.11 已修复，经 `sh -c` 探测） |
| 小内存机容器反复重启 | buffer pool 过大被 OOM | 脚本自动收敛；或 `MARIA_BUFFER_POOL=256M` |
| 页面变形/卡片错位 | 旧版并排网格半宽 | v2.2.11 已改为上下排列单列全宽 |

---

## 11. 版本与升级

- 升级管理端：`docker compose` 拉取新镜像后 `./deploy.sh up -d --build`，`init_schema()` 自动补齐表结构/字段，无需手工迁移。
- 节点侧：重新生成节点目录并重新下载安装脚本即可（节点数据目录保留，不受影响）。
