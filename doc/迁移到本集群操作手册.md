# 把现有数据库迁移到 Custos 集群 · 操作手册（小白版）

> 适用版本：v2.4.0（数据迁移向导）
> 入口：登录 Custos 管理后台 → 菜单「数据迁移向导」（页面路径 `/migration`）
> 一句话说明：这个向导帮你把**别的机器上已经跑着的 MariaDB/MySQL** 整库搬进 **Custos 托管的 MariaDB 集群**，尽量不停机、可追平、可重试。

---

## 一、先确认：你的源库能不能迁

| 源库 → 目标 | 能不能迁 | 怎么搬 |
|---|---|---|
| MariaDB → MariaDB（同引擎） | ✅ 支持 | 默认可「增量追平」（搬完还能持续同步，切的时候差得少） |
| MySQL 5.7 → MariaDB 12.3.3 | ✅ 支持 | 停写后一次性拷贝（不能增量追平） |
| MySQL 8.0 及以上 → MariaDB | ❌ 暂不支持 | 系统会直接拦下，提示需先做排序规则/认证插件换算 |

另外请注意：
- **系统库不搬**：`mysql`、`performance_schema`、`information_schema`、`sys` 以及 Custos 自己的库会自动排除。
- **账号和权限不随库迁移**：目前只搬「数据」，源库里的用户/授权不会自动过来，搬完要自己在目标节点重建账号。
- 源库**建议开启 GTID**（同引擎桥接追平需要）；跨引擎（MySQL 5.7→MariaDB）不需要。

---

## 二、开始前准备（ checklist ）

- [ ] 目标节点**已经用 Custos 装好** MariaDB 12.3.3（容器化或裸机都行），且管理器能连上它。
- [ ] 源库地址、端口、账号、密码备好（账号最好用 `root`，或至少能读全库、能导出）。
- [ ] 网络通：管理器能访问「源库端口」和「目标节点端口」。
- [ ] 心里有数：要搬哪些库？全搬还是只搬几个业务库？

---

## 三、跟着界面走（共 5 步）

界面顶部有一条**步进条**（1 录入源 → 2 目标与通道 → 3 执行迁移 → 4 停桥切换 → 5 收尾回收），每步填完点按钮即可。

### 第 1 步：录入源（告诉向导“从哪搬”）
1. 填 **源主库地址 / 端口 / 账号 / 密码**（端口默认 3306，账号默认 root）。
2. 点 **「🔍 探测源集群」**。
3. 稍等几秒，界面会显示：版本、数据量(GB)、GTID 是否开启、有哪些用户库。
4. 在下方库列表里**勾选要迁移的库**（默认全选用户库）。只想搬几个就取消勾，或填「仅迁移选中库」那行（逗号分隔，如 `app_db,order_db`，留空=全部）。
5. 点 **「下一步：配置目标 →」**。

> 小提示：这一步只是“看一眼”，不会动源库任何数据。

### 第 2 步：配置目标与通道（告诉向导“搬到哪、怎么搬”）
1. 填 **目标节点地址 / 端口 / root 密码**。
2. 填 **目标版本**：去目标节点执行 `SELECT VERSION();`，把返回的那串原文（如 `12.3.3-MariaDB`）粘进来。
3. 选 **目标节点形态**：容器化 MariaDB（默认）或裸机 MariaDB。
4. 选 **迁移通道**（系统已按数据量推荐，可改）：
   - **A 逻辑通道（默认）**：导出用户库再导入，最通用、跨版本最安全，适合中少量数据。
   - **B 物理通道**：用 `mariabackup` 整盘热备恢复，适合 **≥ 500GB 的大库**，但**仅限 MariaDB→MariaDB 同引擎**（MySQL 5.7 源只能选 A）。
5. （选了 B 物理通道才需要）填源端 `my.cnf` 路径和数据目录——每个人装的位置不同，必须显式填，否则备份工具找不到。
6. 填 **迁移任务名称**（随便起，便于识别）。
7. 点 **「✓ 创建迁移任务并继续」**。

### 第 3 步：执行迁移（真正开始搬，建议先预检）
1. 先点 **「🛡 迁移前兼容性预检（dry-run）」**：它**不搬数据**，只扫一遍结构、试跑一遍，把会炸的不兼容项（如某些全文索引）提前报出来。看到「✓ 预检通过」再继续；有「阻断」项先解决。
2. 然后按顺序点三个 **「执行」** 按钮，每点一个等它跑完（界面有进度条和实时日志，每 1.5 秒刷新）：
   - **数据种子**：把源库导出并恢复到目标（这一步最耗时）。
   - **建立桥接**：目标连上源做复制，开始增量追平（仅同引擎有；跨引擎这步会提示不支持，跳过即可）。
   - **一致性校验**：比对两边行数，确认数据对得上。
3. 任一步**失败可以重试**——再点一次「执行」即可，不会从头重来。

> 进度条百分比：种子 45% + 桥接 15% + 校验 20%，剩下的留给切换和收尾。

### 第 4 步：停桥切换（cutover，需人工确认）
确认：**校验已通过 + 复制已追平**（两边数据一致）后，再做这步。
1. 点 **「⚠ 执行停桥切换」**，弹窗再点 **「确认切换」**。
2. 它会：停止目标对源的复制 → 清除桥接通道 → 把目标节点登记进 Custos（之后由 monitor 自动接管 HA）。
3. **VIP（虚拟 IP）需要你在外面手动切**：Custos 在这个场景不会自动接管 VIP，请按你们原先的方式把流量切到新主。

> 此操作不可逆转，动手前务必确认数据已追平。

### 第 5 步：收尾回收（cleanup）
1. 点 **「回收源端账号 / 老主只读」**：向导会收回它在源端建的复制账号，并把老主置为**只读暖备**（先留着，观察一段时间没问题再下线）。
2. 看到「✓ 迁移完成」即全部结束。

---

## 四、两种“通道”怎么选（一句话版）

- **数据量 < 500GB**：用 **A 逻辑通道**（默认就行，省心）。
- **数据量 ≥ 500GB 且是 MariaDB→MariaDB**：用 **B 物理通道**（整盘备份恢复更快）。
- **源是 MySQL 5.7**：只能 **A 逻辑通道**（不能物理、也不能增量追平）。

---

## 五、收尾时两个容易忘的点

1. **VIP 要手动切**：切流那一步 Custos 不接管 VIP，记得在外面把虚拟 IP 指向新主。
2. **老主先留作暖备**：第 5 步会把老主设成只读并保留，别急着删；观察稳定后再下线。
3. **账号权限要另建**：库搬过来了，但源库的用户和授权没过来，业务连不上时在目标节点补建账号。

## 六、常见问题

**Q：探测源集群失败？**
A：先确认地址/端口/账号密码对，且管理器能网络连通源库（防火墙、安全组放行端口）。源库如果是 MySQL，也能探，但版本若是 8.0+ 会在后面被拦。

**Q：预检报“阻断”怎么办？**
A：预检是好事，它在搬数据前拦下了必炸项（比如某些全文索引语法）。按它给的提示修源库结构，或只迁不含该表的库，再重跑预检。

**Q：某一步失败了能重来吗？**
A：能。直接在失败那步再点一次「执行」即可，向导支持重试，不会把前面已完成的步骤重做。

**Q：MySQL 8.0 源为什么不让迁？**
A：MySQL 8.0 改了排序规则和认证插件，直接搬进 MariaDB 会不兼容，当前版本需要先做换算，暂未提供自动流程。可用 MariaDB 源，或先用 MySQL 5.7 过渡。

**Q：迁完业务连不上？**
A：多半是账号没过来（见第五节第 3 点），去目标节点用 `root` 把业务账号和授权重建一遍。
